# Desktop Python training, Java Android inference

The collection APK retains the original model. Training and promotion below are
explicit desktop operations. They do not run during app builds. The Android app
uses Java/XML and its existing CameraX/MediaPipe worker; it never loads Python,
scikit-learn, joblib, raw recordings, or public training images.

## Setup and inputs

Install 64-bit Python **3.12** on the training PC and use the existing Android
Studio JDK/Gradle toolchain. From the project root in PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r tools/vowel-training/requirements-lock.txt
.\.venv\Scripts\python.exe -m unittest discover -s tools/vowel-training -p 'test_*.py'
```

The lock pins scikit-learn 1.9.1 and its resolved dependencies. Python 3.9 is too old
for this setup. Building or using the APK needs no desktop Python installation.

Prepare the original SignAlphaSet v2 archive, manifest, and `landmarks.csv` using
the Java workflow in [TRAINING.md](TRAINING.md). Their original duplicate-group
splits remain fixed, including J/Z exclusions and CC BY 4.0 attribution. An existing
landmark extraction can be reused; nothing downloads during normal builds/tests.

Place the latest private phone export in the ignored `phone-samples` folder. The
commands below use `phone-samples/training-validation.zip`. Do not commit these
recordings or copy them into app assets. Use one latest ZIP containing all sessions,
rather than combining several overlapping exports from the same phone.

## Prepare and fit a candidate

```powershell
.\gradlew.bat :recognition-training:run --args='refine prepare app/build/vowel-work/landmarks.csv app/build/vowel-work/vowel-dataset/manifest.tsv phone-samples/training-validation.zip app/src/main/assets/vowel_forest.bin app/build/refinement/features.jsonl'
.\.venv\Scripts\python.exe tools/vowel-training/refine.py fit --features app/build/refinement/features.jsonl --output app/build/refinement/candidate-01
.\gradlew.bat :recognition-training:run --args='refine verify app/build/refinement/candidate-01/candidate.bin app/build/refinement/candidate-01/parity-features.jsonl app/build/refinement/candidate-01/python-predictions.jsonl'
```

The Java preparer validates ZIP identities, schema, timing, labels, and split groups.
It excludes incomplete clips, while retaining complete clips with missed tracking
or unusable geometry. It also retains public manifest images without landmarks.
Exported features are generated by the same Java code used in Android.
The recorder observes every analyzed result on the existing tracking worker,
including no-hand results, before UI coalescing. Replay uses camera inference
timestamps for the hold/gap rules and relative receipt times for recognition delay.

Training compares the original 63 coordinates with `wrist-palm-geometry-v2` (93
features). Both use aspect-correct coordinates, wrist subtraction, and palm-size
normalization. The extra features are three bend cosines per finger, ten pairwise
fingertip distances, and five fingertip-to-base distances. Coordinate features
retain orientation. Degenerate/non-finite geometry is rejected and counted.

Eight forests are trained: feature set 63/93, maximum depth 12/20, and minimum leaf
size 2/5. All use 256 trees, square-root feature selection, seed 470, and an 8,192-leaf
per-tree bound for the Android reader. All six categories have equal weight; each
category splits weight equally between public/phone examples, with equal phone
clip weight. Training-only mirrors share each original example's weight and split.

Validation-only threshold search covers scores 0.40–0.90 and margins 0.05–0.30 in
0.05 steps. Ranking first prefers candidates meeting phone acceptance gates and
public A/I/U regression limits, then E/O macro F1, vowel macro F1, public macro F1,
and lower thresholds. The 500 ms hold and 250 ms maximum inference gap are unchanged.
Test examples never enter fitting or candidate/threshold selection.

The binary v2 stores feature metadata, thresholds, tree structure, and normalized
six-category leaf distributions. Java casts inputs to float32 at tree branches and
averages leaf distributions to match scikit-learn. Scores are model support, not
calibrated real-world probabilities. Legacy binary v1 remains readable.

Java verify checks every score within `1e-6` and checks displayed letters throughout
phone sequences, including mirrored fixtures. It writes a checksum-bound
`java-verification.json`. Candidate folders are frozen and are not overwritten.

## Final evaluation and guarded packaging

After the candidate is frozen, collect the final test session and export the latest
ZIP as `phone-samples/final.zip`. Keep training/validation sessions unchanged.

```powershell
.\gradlew.bat :recognition-training:run --args='refine prepare app/build/vowel-work/landmarks.csv app/build/vowel-work/vowel-dataset/manifest.tsv phone-samples/final.zip app/src/main/assets/vowel_forest.bin app/build/refinement/final-features.jsonl'
.\.venv\Scripts\python.exe tools/vowel-training/refine.py evaluate --features app/build/refinement/final-features.jsonl --output app/build/refinement/candidate-01
.\gradlew.bat :recognition-training:run --args='refine verify app/build/refinement/candidate-01/candidate.bin app/build/refinement/candidate-01/parity-features.jsonl app/build/refinement/candidate-01/python-predictions.jsonl'
.\.venv\Scripts\python.exe tools/vowel-training/refine.py package --output app/build/refinement/candidate-01
```

Evaluation refuses changed training/validation data or baseline/public provenance.
It does not tune thresholds and refuses to overwrite its first test report. It
loads only the checksum-verified joblib estimator generated in that candidate folder;
phone ZIP input is always JSON, never an executable Python serialization.

Reports separate per-frame classification from stabilized clip results and include
precision/recall, confusion matrix, rejection, tracking coverage, recognition delay,
and baseline comparisons. Missing tracking and rejected vowels count as misses.
Any incorrect stabilized vowel makes a clip unsuccessful, even if corrected later.
The existing public test split is a previously evaluated regression set.

Packaging requires E/O precision >=90%, recall >=80%, and each letter's F1 above
baseline; A/I/U precision/recall may not drop more than five percentage points.
Other false detections must be <=5%. A complete 80-hold test session and fresh Java
parity verification are required. Public A/I/U regression limits also apply. With
one participant these are session-separated measurements, not unseen-person results.

Only a passing candidate produces `android-bundle` with `vowel_forest.bin`, model
properties/checksums, and evaluation notes. Review that bundle, then explicitly
copy its model/properties into app assets and update model documentation/fixtures.
Run the full Android checks and test the resulting APK on a phone. The tools do
not overwrite app assets or publish GitHub changes. Retain the original model if
targets fail; collect additional training/validation data and use a fresh final
test session for the next refinement.

## Software checks and provenance

`smoke_fixture.py` can build synthetic collection-format inputs from existing public
landmarks to exercise the entire pipeline. These repeat public examples and must
never be reported as phone accuracy or used to replace the bundled model.

```powershell
.\.venv\Scripts\python.exe tools/vowel-training/smoke_fixture.py app/build/vowel-work/landmarks.csv app/build/vowel-work/vowel-dataset/manifest.tsv app/build/refinement-smoke
```

Keep the dataset/model provenance already under `third_party`. The Python trainer
uses [scikit-learn's documented forest behavior](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.RandomForestClassifier.html);
see [training-tool notices](third_party/refinement-training/README.md). Every input
archive and model is checksum-recorded. Training outputs, environments, phone
samples, and generated fixtures stay outside clean project deliveries.
